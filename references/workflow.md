# 视频拆解工作流

## 1. 项目目录

```text
project/
├── inputs/        可选复制的产品资料和投放数据
├── work/          inventory.json、联系表、音频和分析JSON
├── qa/            验证JSON与Excel预览
└── deliverables/  同名正式xlsx与整合型单文件html
```

源视频默认保持原位置，只读处理；不要为了整理目录而移动或重命名用户文件。

## 2. 证据采集

对每条视频至少记录：原始文件名、完整路径、时长、宽高、帧率、音轨；0–3秒完整字幕/口播语义和第一视觉；人物身份、场景、商品出现时点、演示、证明、价格和行动号召；每次叙事转折的时间点；用户能直接看见的证据与只能听到的宣称。

联系表用于定位，不能代替观看完整视频。音频无法转写时人工读取字幕并标记“口播未独立转写”。

## 3. 逐段拆解

按“沟通任务发生变化”切段，而不是机械地每3秒切一段。每段输出起止时间、画面/口播/字幕概述、主要内容功能、对停留/信任/点击/成交的作用、可复刻点和风险/缺口。

## 4. 四层分析

- **停留层**：用户为什么不划走，例如事件、问题、身份、反常识、视觉奇观、结果预期或价格机会。
- **承接层**：开头之后为什么继续看，检查信息推进、证据更新、节奏变化和新问题。
- **信任层**：用户为什么相信，检查真人、演示、原料、配料、生产、口碑、数据、权威、对比或购买所得。
- **交易层**：为什么买、为什么现在买，检查需求强度、异议处理、首次尝试门槛、真实价格机制、真实稀缺与行动路径。

## 5. 复刻输出

每条素材必须包含：必须保留的成交因果链；可以替换的人物、场景、话术和镜头；团队拍摄清单；可复用脚本骨架；下一轮只改变一个变量的A/B测试；成功指标；不能虚构的事实。

## 6. 关键画面证据

每条素材通常选择3–5张：

1. 开头钩子帧；
2. 核心信任或证明帧；
3. 商品、使用或结果展示帧；
4. 异议处理或交易加速帧；
5. 仅在确有新增证据价值时补充一帧。

每张图必须记录素材编号、证据编号、时间戳、证据角色、支持的结论和证据边界。用 `python scripts/extract_evidence_frames.py` 从原视频按时间戳提取；不能用联系表截图代替清晰证据帧。Excel正文通过证据编号引用图片。

## 7. 数据判断

- 只有视频：判断结构、跑量条件和风险。
- 有播放数据：可判断停留和承接，但不能单独证明成交。
- 有点击数据：可判断商品兴趣，不等于购买有效。
- 有订单、成交成本、净ROI：可判断素材级成交效率。
- 同模型多条独立脚本有量且效率稳定：才可判断模型级验证。

## 8. 横向复盘

回答素材覆盖哪些成交引擎、哪些只是换皮、哪些模型由单条素材驱动、哪些人群/场景/异议没有覆盖、素材池中拉新/说服/收割/补量如何分配，以及优先测试的3–5个单变量。

## 9. 双格式交付

先完成并验证 Excel，再从最终 Excel 转换整合型单文件 HTML：

```text
python scripts/xlsx_to_single_html.py deliverables/报告.xlsx
```

默认生成 `deliverables/报告.html`。页面不能是电子表格网页版；必须把相同内容重组为结论、时间轴、复刻方案和证据图集。暂时移动或忽略中间图片目录后再次打开 HTML，确认文字、内嵌图片和大图查看仍然可用。
